## Endpoint

```
POST https://llm.orchid.ac/v1/chat/completions
```

OpenAI-compatible. Accepts the same request body as `POST /v1/chat/completions` on the OpenAI API, plus an optional `orchid` config object.

## Request

### Headers

| Header | Value |
|--------|-------|
| `Authorization` | `Bearer <your-orchid-key>` |
| `Content-Type` | `application/json` |

### Body

All standard OpenAI chat completion fields are supported. Key fields:

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `model` | string | required | Use `orchid01` |
| `messages` | array | required | Conversation history |
| `max_tokens` | integer | `4096` | See [Max Tokens](/guides/max-tokens) |
| `temperature` | number | `0.1` | Ignored in thinking mode (fixed at 1.0) |
| `stream` | boolean | `false` | Stream response tokens |
| `tools` | array | — | Tool definitions (JSON Schema) |
| `tool_choice` | string/object | `auto` | Tool selection behaviour |
| `orchid` | object | — | Orchid-specific config (see below) |

### The `orchid` config object

Optional body key **`orchid`** controls Orchid-specific behaviour on **`/v1/chat/completions`** only (not on [`/v1/messages`](/api-reference/messages)).

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `thinking` | boolean | `false` | Enable deep reasoning mode |
| `thinking_effort` | string | — | When thinking is on: `none`, `low`, `medium`, or `high` |
| `provenance` | boolean | `false` | Set `true` to have the model cite a `role: "tool"` message for every sentence and check each claim against it with deterministic code (streaming and non-streaming). One tool message is one source, however many results it holds. See [Provenance](/guides/provenance). |
| `sources` | array | — | With `provenance`: full original tool outputs, as `[{"tool_call_id": "...", "content": "..."}]`, for any you shortened in `messages`. Quotes and offsets are checked against these. |
| `memory` | boolean | `false` | Set `true` to enable persistent per-API-key memory. Facts from past conversations are retrieved and injected as context; new exchanges are written back asynchronously. Skipped for zero-retention keys. |

See [Provenance](/guides/provenance) and [Rate limits](/api-reference/rate-limits).

<Note>
  The built-in `orchid-finance` tool suite runs automatically on every request (see [Tool calling](/guides/tool-calling)). If it — or a `tools` array you passed — triggers a tool call, `stream: true` is overridden to a non-streamed response: the model must finish its tool-call loop before it can return anything.
</Note>

## Response

Standard OpenAI chat completion response, plus an `orchid` field:

```json
{
  "id":      "chatcmpl-abc123",
  "object":  "chat.completion",
  "model":   "orchid01",
  "choices": [{
    "index":         0,
    "message": {
      "role":    "assistant",
      "content": "According to the filing..."
    },
    "finish_reason": "stop"
  }],
  "usage": {
    "prompt_tokens":     1240,
    "completion_tokens": 380,
    "total_tokens":      1620
  },
  "orchid": {
    "mcp_server":              "orchid-finance",
    "mcp_iterations":          1,
    "mcp_tool_calls":          [],
    "provenance": {
      "version":   1,
      "checked":   true,
      "sources":   [{ "id": "S1", "tool_call_id": "call_abc", "tool": "get_filing" }],
      "coverage":  {
        "sentences": 6, "verified": 4, "derived": 1, "inferred": 1, "unsupported": 0,
        "wrong": 0, "miscited": 0, "uncited": 0, "exempt": 1, "unchecked": 0,
        "score": 0.8333, "supported_score": 1.0
      },
      "sentences": [...],
      "lineage":   {}
    },
    "provenance_coverage": { "sentences": 6, "verified": 4, "derived": 1, "...": "same as provenance.coverage" }
  }
}
```

`mcp_server`, `mcp_iterations`, and `mcp_tool_calls` are always present — see [Tool calling](/guides/tool-calling#mcp-audit-fields).

`provenance` and `provenance_coverage` appear only when you set `orchid.provenance: true`:

| Field | Description |
|-------|-------------|
| `provenance` | The full result: `checked`, `sources`, per-sentence `sentences` (status, citations with `offsets` into your tool messages, and claims), `coverage`, and `lineage`. On a turn that ends in tool calls it is `{"checked": false, "reason": "tool call turn"}`. A citation may carry `cited_as` (the model named a source the quote was not in, so it was checked where the quote is), and a claim may carry `declared` — the entity and field the model stated for that figure, which Orchid confirmed by lookup. |
| `provenance_coverage` | A copy of `provenance.coverage`: sentence counts per status, `score`, `supported_score`, `strict_score`, `failed`, and `figures` / `figures_declared` (how many cited figures the model stated outright) |

With `stream: true`, the same `orchid` object arrives in one extra chunk with an empty `delta`, sent after the last content chunk and before `data: [DONE]`. See [Provenance](/guides/provenance#reading-results) for the full schema and how to read it.

## Error responses

**Format:** Failures return an **OpenAI-compatible** JSON body with a top-level `error` object (`message`, `type`, `code`, `param`). The same shape is used for gateway errors across Orchid so OpenAI SDKs parse errors predictably.

Errors follow that format, for example:

```json
{
  "error": {
    "message": "Invalid API key",
    "type":    "authentication_error",
    "code":    "invalid_api_key",
    "param":   null
  }
}
```

| Status | Type | Meaning |
|--------|------|---------|
| `400` | `invalid_request_error` | Malformed request body |
| `401` | `authentication_error` | Invalid or missing API key |
| `429` | `rate_limit_error` | Rate limit exceeded — see [Rate limits](/api-reference/rate-limits) |
| `502` | `upstream_error` | Upstream provider error |
