---
title: "Event kinds"
description: "The built-in kinds Orchid records, their fields, and what each counts as."
---

Your own kinds start with `x.` ([Event types](/send/event-types)). These are built in. A key may send the ones marked **you send**; Orchid writes the rest.

**Counts as**: A = activity, W = work, C = comms, G = governance.

## AI use

| Kind | `attrs` | Counts as |
| --- | --- | --- |
| `ai.message` | `role` (required), `surface`, `model` | A, W, G |
| `ai.request` | `model`, `provider`, `input_tokens`, `output_tokens`, `latency_ms`, `status_code`, `cost_usd`, `saving_usd`, `baseline_model`, `route`, `agent`, `run` | A |
| `ai.tool_call` | `tool` (required), `system`, `action`, `outcome` | A |
| `read` | `system` (required), `seen`, `kept`, `rules`: Orchid read an item for a request | |
| `reaction` | `label` (required): how a person reacted to an answer | W |
| `routing.feedback` | `kind` (required) | |

## Studio

`studio.automation.run`, `studio.dashboard.run`, `studio.schedule.run` (A), `studio.dm` (A, C, G).

`GET /v1/record/kinds` returns this list for your firm, with each kind's schema, and your own kinds after it.
